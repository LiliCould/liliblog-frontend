# 立里博客前端重构 - 开发规范文档

## 1. 包管理规范

### 1.1 包管理工具

**必须使用 Yarn 作为唯一的包管理工具**，禁止使用 npm、pnpm 等其他任何包管理工具。

```bash
# 正确：使用 yarn 安装依赖
yarn add <package-name>
yarn add -D <package-name>

# 正确：使用 yarn 移除依赖
yarn remove <package-name>

# 正确：使用 yarn 更新依赖
yarn upgrade <package-name>
yarn upgrade-interactive

# 正确：使用 yarn 安装所有依赖
yarn install

# 错误：禁止使用 npm
npm install <package-name>      # ❌ 禁止
npm i <package-name>            # ❌ 禁止

# 错误：禁止使用 pnpm
pnpm add <package-name>         # ❌ 禁止
pnpm install                    # ❌ 禁止
```

### 1.2 依赖版本一致性

- 所有依赖版本锁定在 `yarn.lock` 文件中
- 提交代码时必须同时提交 `yarn.lock` 文件
- 不允许手动修改 `yarn.lock` 文件
- 使用 `.yarnrc.yml` 配置 Yarn 行为

### 1.3 项目已配置 Yarn

项目已使用 Yarn 作为包管理工具，相关配置文件：
- `.yarnrc.yml` - Yarn 配置文件
- `yarn.lock` - 依赖锁定文件
- `.yarn/` - Yarn 缓存目录

## 2. UI/UX 设计规范

### 2.1 设计规范遵循原则

**必须严格遵循已确定的《UI 风格规范文档》**，任何设计变更均需经过审核确认。

### 2.2 禁止事项

- **绝对禁止使用具有明显 AI 生成特征的配色方案**
  - 禁止 AI 风格渐变色（如蓝紫渐变、彩虹渐变等）
  - 禁止过度平滑的过渡效果
  - 禁止 Glassmorphism（玻璃拟态）效果
  
- **禁止偏离项目主色调及配色体系**
  - 主色：Indigo 700（#4338ca）
  - 强调色：Chartreuse（#a3e635）、Hot Magenta（#e11d48）
  - 中性色：Stone 系列或纯黑/纯白

### 2.3 必须遵循的设计特征

| 特征 | 要求 |
|------|------|
| 圆角 | 直角（0px）或微圆角（2px），禁止大圆角 |
| 阴影 | 硬阴影偏移（Hard Shadow Offset），禁止模糊阴影 |
| 边框 | 粗边框（2px），用于区分层级 |
| 动效 | linear 或 steps()，禁止 ease-in-out |
| 过渡 | 0-50ms 硬切，禁止 300ms 平滑淡入 |
| 质感 | 可添加噪点、故障效果，禁止玻璃拟态 |

### 2.4 设计变更流程

1. 提出变更需求
2. 对照《UI 风格规范文档》评估
3. 团队审核确认
4. 更新设计文档
5. 实施变更

## 3. 代码注释规范

### 3.1 注释语言

**所有代码注释必须使用中文编写**，确保团队成员能够准确理解代码意图。

### 3.2 注释要求

注释内容必须清晰、准确、完整，能够有效帮助开发人员理解：
- 代码功能
- 实现逻辑
- 注意事项
- 边界情况

### 3.3 必须注释的场景


#### 3.3.2 复杂逻辑注释

```typescript
// 处理双令牌认证的无感刷新逻辑
// 当 Access Token 过期时，自动使用 Refresh Token 获取新的 Access Token
// 刷新成功后重试原请求，刷新失败则清除登录状态并跳转登录页
request.interceptors.response.use(
  (response) => response.data,
  async (error) => {
    const originalRequest = error.config
    
    // 判断是否为 401 错误且未重试过
    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true
      
      try {
        // 调用刷新接口，Refresh Token 自动通过 Cookie 携带
        const res = await axios.post('/auth/refresh')
        const { accessToken } = res.data.data
        
        // 更新本地存储的 Access Token
        localStorage.setItem('accessToken', accessToken)
        
        // 使用新 Token 重试原请求
        originalRequest.headers.Authorization = `Bearer ${accessToken}`
        return request(originalRequest)
      } catch {
        // 刷新失败，清除登录状态并跳转登录页
        localStorage.removeItem('accessToken')
        window.location.href = '/login'
      }
    }
    
    return Promise.reject(error)
  }
)
```

#### 3.3.3 关键业务逻辑注释

```typescript
// 文章状态枚举
// 0: 审核中 - 文章已提交但尚未通过审核
// 1: 已发布 - 文章已通过审核并对外展示
// 2: 草稿 - 文章仅作者可见，未提交审核
export enum ArticleStatus {
  PENDING = 0,
  PUBLISHED = 1,
  DRAFT = 2
}

// 判断当前用户是否有权限查看文章
// 管理员可查看所有状态文章，普通用户仅可查看已发布文章
// 作者本人可查看自己的所有文章
export const canViewArticle = (article: Article, user?: UserInfo): boolean => {
  // 已发布文章对所有用户可见
  if (article.status === ArticleStatus.PUBLISHED) return true
  
  // 未登录用户只能查看已发布文章
  if (!user) return false
  
  // 管理员可查看所有文章
  if (user.role === 0) return true
  
  // 作者可查看自己的文章
  return article.creator.id === user.id
}
```

#### 3.3.4 组件 Props 注释

```vue
<script setup lang="ts">
/**
 * 文章卡片组件
 * 用于在文章列表中展示文章摘要信息
 */
interface Props {
  /** 文章数据对象，包含标题、摘要、封面等信息 */
  article: Article
  /** 是否处于加载状态，默认 false */
  loading?: boolean
  /** 是否显示操作按钮（编辑、删除），默认 true */
  showActions?: boolean
}

withDefaults(defineProps<Props>(), {
  loading: false,
  showActions: true,
})

const emit = defineEmits<{
  /** 点击卡片事件，返回文章 ID */
  click: [id: number]
  /** 删除文章事件，返回文章 ID */
  delete: [id: number]
}>()
</script>
```

### 3.4 注释格式规范

| 场景 | 格式 | 示例 |
|------|------|------|
| 单行注释 | `// 注释内容` | `// 获取当前登录用户信息` |
| 多行注释 | `/* ... */` | `/* 处理分页逻辑 ... */` |
| 文档注释 | `/** ... */` | 函数、组件、类型定义 |
| TODO | `// TODO: 说明` | `// TODO: 后续添加缓存逻辑` |
| FIXME | `// FIXME: 说明` | `// FIXME: 处理边界情况` |

### 3.5 禁止事项

- 禁止无意义的注释（如 `// 定义变量`）
- 禁止注释与代码逻辑不符
- 禁止遗留调试代码而不加注释说明
- 禁止使用英文注释（除非引用第三方库 API）

## 5. Git 工作流规范

### 5.1 分支管理

| 分支 | 用途 | 保护规则 |
|------|------|----------|
| `main` | 生产环境 | 禁止直接推送，需 PR 合并 |
| `develop` | 开发环境 | 禁止直接推送，需 PR 合并 |
| `feature/*` | 功能开发 | 开发完成后合并到 develop |
| `fix/*` | Bug 修复 | 修复完成后合并到 develop |

### 5.2 提交信息规范

格式：`<type>: <subject>`

| Type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `style` | 样式调整（不影响功能） |
| `refactor` | 代码重构 |
| `docs` | 文档更新 |
| `chore` | 构建/工具相关 |
| `test` | 测试相关 |

示例：
```bash
feat: 新增文章点赞功能
fix: 修复评论列表加载失败问题
style: 调整文章卡片边框样式
refactor: 重构用户认证逻辑
docs: 更新接口对接文档
```

### 5.3 代码评审流程

1. 功能开发完成后，从 `feature/*` 分支发起 PR 到 `develop`
2. PR 描述需说明变更内容、测试情况
3. 至少 1 人评审通过后方可合并
4. 合并后删除功能分支

## 7. 测试规范

### 7.1 测试框架

- 单元测试：Vitest + Vue Test Utils
- E2E 测试：Playwright（可选）

### 7.2 测试文件命名

- 单元测试：`*.spec.ts` 或 `*.test.ts`
- 与源文件同目录或 `__tests__` 目录

### 7.3 测试覆盖目标

- 单元测试覆盖率：> 80%
- 核心逻辑必须覆盖
- 边界情况必须覆盖

### 7.4 测试示例

```typescript
// ArticleCard.spec.ts
import { describe, it, expect } from 'vitest'
import { mount } from '@vue/test-utils'
import ArticleCard from './ArticleCard.vue'

describe('文章卡片组件', () => {
  it('正确渲染文章标题', () => {
    const wrapper = mount(ArticleCard, {
      props: {
        article: {
          id: 1,
          title: '测试文章',
          // ...
        }
      }
    })
    
    expect(wrapper.text()).toContain('测试文章')
  })
  
  it('点击卡片触发 click 事件', async () => {

      props: { article: { id: 1, title: '测试' } }

    await wrapper.trigger('click')
    
    expect(wrapper.emitted('click')).toBeTruthy()
    expect(wrapper.emitted('click')![0]).toEqual([1])
  })
})
```
