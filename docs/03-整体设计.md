# 立里博客前端重构 - 完整设计文档 v3.0

> 日期：2026-05-17

---

## 设计哲学：新人文主义界面（Neo-Humanist Interface）

拒绝算法美学的核心并非回归机械粗野，而是重建**"数字人格的物质化"（Materialization of Digital Identity）**。界面不再是中性的信息容器，而是博主精神气质的外延——通过 Emoji 的情感标点、头像的人格锚点、封面图的自然色谱，将"人"的不完美与偏好重新写入像素。

同时，保留**反算法的独立身份宣言**——通过噪点纹理、故障艺术文字、机械刚性动效，在温和的现代主义框架内注入有脾气的视觉张力。

## 1. 色彩系统：内容驱动色谱（Content-Chromatic Architecture）

彻底放弃背景渐变，将色彩主动权交还给内容本身。

### 1.1 画布层（Canvas）

| Token | 亮色模式 | 暗色模式 | 用途 |
|-------|----------|----------|------|
| `--bg-canvas` | `#ffffff` | `#0f172a` (Slate-900) | 页面背景 |
| `--bg-surface` | `#f8fafc` (Slate-50) | `#1e293b` (Slate-800) | 卡片、面板 |
| `--bg-elevated` | `#ffffff` | `#334155` (Slate-700) | 弹窗、下拉 |

暗色模式背景非纯黑（`#000000`），保留 Slate-900 的微弱蓝紫底调，维持深夜阅读的视觉舒适度。

### 1.2 主色（Primary）

| Token | 值 | 用途 |
|-------|-----|------|
| `--primary` | `#4f46e5` (Indigo-600) | 链接、按钮、激活态、分类高亮 |
| `--primary-foreground` | `#ffffff` | 主色上的文字 |
| `--primary-hover` | `#4338ca` (Indigo-700) | Hover 态 |

以纯平面色块（Flat Color Blocking）形式出现，不加任何透明度层或渐变蒙版。

### 1.3 功能强调色（Functional Accent）

| Token | 值 | 用途 |
|-------|-----|------|
| `--accent-toxic` | `#a3e635` (Chartreuse) | 状态筛选下划线、Hover 高亮、光标 |
| `--accent-rose` | `#f43f5e` (Rose-500) | 点赞数、热度、删除、错误 |
| `--accent-amber` | `#f59e0b` (Amber-500) | "新文章"角标、警告 |

强调色以几何色块（矩形下划线、方形光标、边框高亮）出现，绝不晕染。

### 1.4 文字色（Typography）

| Token | 亮色模式 | 暗色模式 | 用途 |
|-------|----------|----------|------|
| `--text-title` | `#0f172a` (Slate-900) | `#ffffff` | 标题 |
| `--text-body` | `#334155` (Slate-700) | `#cbd5e1` (Slate-300) | 正文 |
| `--text-meta` | `#64748b` (Slate-500) | `#94a3b8` (Slate-400) | 元数据、时间 |

### 1.5 暗色模式层级区分

Surface 与背景通过 **1px 硬边框**（`border-slate-700`）区分层级，拒绝 Glassmorphism 的半透明模糊。对比度 ratio 保持在 15:1 以上。

### 1.6 色彩层级逻辑

封面图的天然色谱成为每篇文章的"环境主题色"，UI 本身退居中性，让内容成为视觉焦点。

采用 **1 : 2.5 : 1 的非对称栏宽比**，总容器宽度约束在 1100–1200px。

- **左侧边栏（Identity Panel）**：Sticky 定位，承载人格化信息（头像、宣言、分类目录、标签云、统计）。
- **中间主内容区（Content Stream）**：自适应宽度，采用**垂直卡片流（Vertical Card Flow）**，每张卡片以 **16:10 或 3:2 的封面图**作为视觉入口，形成"图–文–元数据"的三段式信息层级。
- **右侧边栏（Discovery Panel）**：随机文章（5篇）+ 标签云。

### 2.2 响应式断点策略

| 断点 | 布局 | 侧边栏处理 |
|------|------|-----------|
| >= 1280px (xl) | 三栏：左侧 280px + 中间自适应 + 右侧 280px | 全部显示 |
| >= 1024px (lg) | 三栏：左侧 240px + 中间自适应 + 右侧 240px | 全部显示，栏宽缩窄 |
| >= 768px (md) | 两栏：左侧 240px + 中间自适应 | 右侧边栏隐藏 |
| < 768px (sm) | 单栏：中间内容区 | 左侧边栏隐藏至抽屉，右侧边栏折叠至底部 |

**移动端侧边栏**：
- 点击汉堡菜单展开左侧边栏抽屉（Drawer）
- 右侧边栏内容折叠到页面底部

### 2.3 特殊页面布局规则

| 页面 | 布局 |
|------|------|
| 首页 (`/`) | Hero 区域（全宽，位于导航栏下方、三栏上方）+ 三栏布局 |
| 文章列表页、文章详情页 | 直接三栏布局，无 Hero |
| 登录 (`/login`) | 独立居中卡片，脱离三栏，背景叠加噪点纹理 |
| 写文章 (`/write`)、编辑 (`/write/:id`) | 独立全宽布局，顶部固定工具栏 |
| 后台管理 (`/admin/*`) | 左侧 Sidebar 导航 + 右侧紧凑内容区 |
| 用户设置 (`/settings`) | 可脱离三栏，或采用两栏（设置菜单 + 内容） |

## 3. 形态语言：柔和几何（Soft Geometry）

### 3.1 圆角规范（Radius Token System）

| Token | 值 | 用途 |
|-------|-----|------|
| `radius-sm` | `6px` (rounded-md) | 输入框、小标签 |
| `radius-md` | `12px` (rounded-xl) | 封面图、内嵌卡片 |
| `radius-lg` | `16px` (rounded-2xl) | 文章卡片容器、面板 |
| `radius-full` | `9999px` | 标签 Pills、徽章、头像 |

**封面图圆角 `12px`**：现代友好，降低攻击性；**卡片容器圆角 `16px`**：大圆角传递 App-like 的年轻感；**标签胶囊形**：当下移动原生设计的主流语法。

### 3.2 阴影规范

采用 **弥散阴影（Diffused Shadow）**，拒绝 Neo-Brutalism 的硬偏移投影：

```css
/* 卡片默认 */
shadow-sm: 0 1px 2px 0 rgba(15, 23, 42, 0.05);
/* 卡片 Hover */
shadow-md: 0 4px 6px -1px rgba(15, 23, 42, 0.1), 0 2px 4px -2px rgba(15, 23, 42, 0.1);
/* 弹窗、下拉 */
shadow-lg: 0 10px 15px -3px rgba(15, 23, 42, 0.1), 0 4px 6px -4px rgba(15, 23, 42, 0.1);
```

### 3.3 边框规范

| 场景 | 边框 | 说明 |
|------|------|------|
| 亮色卡片 | `1px solid #e2e8f0` (Slate-200) | 极淡分隔 |
| 暗色卡片 | `1px solid #334155` (Slate-700) | 硬边界区分层级 |
| 代码块 | `2px solid #000000` (亮色) / `2px solid #292524` (暗色) | 粗边框，机械感 |
| 引用块 | `4px solid #a3e635` (Chartreuse) | 毒性色左边界 |

## 4. 排版系统：中文舒适排版（CJK-Optimized Typography）

### 4.1 字体栈

```css
/* 正文与标题 */
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;

/* 元数据、数字、代码 */
font-family: "JetBrains Mono", "Fira Code", "SF Mono", "Cascadia Code", monospace;
```

等宽字体的机械等距感与正文的流动感形成**字体层面的冲突美学（Typographic Tension）**。

### 4.2 字号与尺度

| 层级 | 字号 | 字重 | 字间距 | 行高 | 用途 |
|------|------|------|--------|------|------|
| Display | `3rem` (48px) | 900 (Black) | `-0.05em` | 1.0 | Hero 主标题 |
| H1 | `2.25rem` (36px) | 800 | `-0.03em` | 1.1 | 页面标题 |
| H2 | `1.5rem` (24px) | 700 | `-0.02em` | 1.2 | 文章标题、区块标题 |
| H3 | `1.25rem` (20px) | 600 | `-0.01em` | 1.3 | 卡片标题 |
| Body | `1rem` (16px) | 400 | `0` | 1.625 | 正文 |
| Mono | `0.875rem` (14px) | 400 | `0` | 1.5 | 日期、标签、代码、阅读数 |
| Caption | `0.75rem` (12px) | 500 | `0.02em` | 1.5 | 辅助信息、徽章 |

### 4.3 排版规则

- **正文基线**：`16px`，`line-height: 1.625`（`leading-relaxed`），中文字体栈优先系统字体（`-apple-system, "Noto Sans SC", sans-serif`），确保跨平台阅读一致性。
- **标题尺度**：文章标题 `24px`（`text-2xl`），`font-weight: 700`，`letter-spacing: -0.02em`，制造紧凑有力的视觉锚点。
- **元数据层**：`14px`（`text-sm`），`text-slate-500`，数字使用等宽字体。
- **标签系统**：`12px`（`text-xs`），`font-weight: 500`，配合浅色背景色块（如 `bg-indigo-50 text-indigo-600`）。
- **行宽（Measure）**：中文最佳行宽为 **680px - 720px**（约 28-32 个汉字），对应 `max-w-2xl`（672px）或自定义 `max-w-[720px]`。
- **段间距**：`space-y-6` 或 `space-y-8`，建立垂直节奏（Vertical Rhythm）。

## 5. 人格化表达层：情感标点与身份锚点

### 5.1 Emoji 作为情感标点（Emotional Punctuation）

标题与分类中自然嵌入 Emoji（如 "最喜欢的动漫 📺"），这是人类表达的非结构化特征，算法生成内容极少自发使用。

### 5.2 头像作为人格锚点（Identity Anchor）

圆形头像置于左侧边栏顶部，配合手写感签名，形成强烈的"此站有人"的心理暗示。

### 5.3 吉祥物/符号（Mascot Symbol）

站点角落放置静态 SVG 符号（如 `<\_/>`），作为视觉签名（Visual Signature），替代算法偏好的抽象插画。

### 5.4 元数据的人文转译

将"随笔"重命名为"心情随写"，将阅读时长写作"阅读时长≈8分"——近似符号与口语化表达降低工具感。

### 5.5 社交链接（Social Links）

左侧边栏底部放置四个平台图标：GitHub、邮箱、哔哩哔哩、Gitee。使用 Lucide 官方图标，悬停时毒性色高亮，新标签页打开。

## 6. 质感层：噪点、故障与机械误差

在完美数字表面制造人为瑕疵，去 AI 化。

### 6.1 全局噪点（Noise Overlay）

在页面顶层叠加一层 `opacity-5` 的噪点 PNG（`pointer-events-none`），模拟胶片颗粒。

```css
.noise-overlay {
  position: fixed;
  top: 0; left: 0; right: 0; bottom: 0;
  pointer-events: none;
  opacity: 0.05;
  background-image: url('/noise.png');
  background-repeat: repeat;
  z-index: 9999;
}
```

### 6.2 故障艺术（Glitch）

- **Hero 主标题**：抖音风格文字闪动动画（`GlitchText` 组件），使用 CSS `text-shadow` 错位 + `clip-path` 切片动画。
- **关键视觉元素**：偶尔使用水平错位切片，Hover 时偏移 2-3px，暗示数字信号的不稳定性。
- **错误态页面**：全面使用故障艺术风格（`ErrorState` 组件）。

### 6.3 打字机效果（TypewriterText）

Hero 副标题 "<技术与生活的分享空间_/>" 使用动态打字机效果，逐字输入，配合闪烁光标。

### 6.4 加载态（LoadingBlock）

- 拒绝旋转 Spinner。
- 骨架屏（Skeleton Screen）使用与卡片一致的圆角与间距。
- 或采用打字机效果、进度条为实体像素块逐个填充。

## 7. 微交互与动效：温和反馈 + 机械刚性混合

### 7.1 主题切换

- 默认跟随 `prefers-color-scheme`。
- 右上角提供手动切换按钮（太阳/月亮图标）。
- 过渡动画改为**硬切（Hard Cut）**或**故障切换（Glitch Transition）**：`0ms` 或 `50ms`，拒绝 `300ms` 的平滑淡入。
- 状态持久化至 `localStorage`。

### 7.2 Easing 规范

| 场景 | Easing | 时长 | 说明 |
|------|--------|------|------|
| 主题切换 | `linear` | 0-50ms | 硬切 |
| 卡片 Hover 位移 | `cubic-bezier(0.4, 0, 0.2, 1)` | 200ms | 温和浮起 |
| 链接 Hover 反色 | `linear` | 0ms | 瞬时切换 |
| 页面转场 | `steps(5)` | 200ms | 百叶窗式块状切换 |
| 打字机光标 | `steps(1)` | 500ms | 闪烁 |

### 7.3 Hover 反馈

- **文章卡片**：整体 `translateY(-4px)` + 阴影加深，营造"可拿起"的物理暗示。
- **链接**：背景色块反色（Background Inversion）—— Hover 时背景变为 Chartreuse，文字反黑，瞬时切换。
- **社交图标**：毒性色高亮，瞬时切换。
- **按钮**：背景色加深 + 轻微 `translateY(-2px)`。

### 7.4 自定义光标（可选）

自定义光标为实体色块（如 12px 的 Chartreuse 正方形），替代默认箭头，增加交互的物理存在感。

## 8. API 接口对接规范

### 8.1 基础配置

| 配置项 | 值 |
|--------|-----|
| 开发环境 BaseURL | `http://localhost:8080` |
| 生产环境 BaseURL | `https://api.lilicould.cn` |
| 认证方式 | Bearer Token (`Authorization: Bearer {accessToken}`) |
| Token 存储 | `accessToken` → `localStorage`；`refreshToken` → `http-only Cookie`（自动携带） |
| 响应格式 | `{ code: 0, msg: "成功", data: ..., time: "..." }`，`code=0` 为成功 |

### 8.2 认证与 Token 刷新策略

**双令牌机制**：
- `accessToken`：短期有效，存储在 `localStorage`，每次请求携带在 `Authorization: Bearer` 头中。
- `refreshToken`：长期有效，存储在 `http-only Cookie`，自动随请求携带。

**无感刷新流程**：
1. Axios 请求拦截器：从 `localStorage` 读取 `accessToken`，附加到请求头。
2. Axios 响应拦截器：捕获 401 状态码。
3. 遇到 401 时，调用 `POST /auth/refresh`（自动携带 `refreshToken` Cookie）。
4. 刷新成功：更新 `localStorage` 中的 `accessToken`，重试原失败请求。
5. 刷新失败（`refreshToken` 也过期）：清除 `localStorage`，跳转登录页，Toast 提示"登录已过期，请重新登录"。

**登出流程**：
- 调用 `POST /auth/logout`（携带 `refreshToken` Cookie）。
- 服务端清除 Redis 中的 `refreshToken`。
- 前端清除 `localStorage` 中的 `accessToken`。
- 跳转首页，Pinia 状态重置。

### 8.3 接口清单与页面映射

#### 8.3.1 标签接口（Tag API）

| 方法 | 路径 | 权限 | 用途 | 对应页面 |
|------|------|------|------|----------|
| GET | `/api/tag` | 公开 | 分页获取标签列表（`name`, `current`, `size`） | 标签云、写文章标签选择 |
| GET | `/api/tag/{id}` | 公开 | 获取指定标签详情 | 标签文章页 |
| POST | `/api/tag` | 管理员 | 添加标签（`name`, `color`） | 后台标签管理 |
| PUT | `/api/tag/{id}` | 管理员 | 修改标签（`name`, `color`） | 后台标签管理 |
| DELETE | `/api/tag/{id}` | 管理员 | 删除标签 | 后台标签管理 |

**标签数据结构**：`{ id, name, color }`，`color` 为标准 CSS 十六进制色值。

#### 8.3.2 分类接口（Category API）

| 方法 | 路径 | 权限 | 用途 | 对应页面 |
|------|------|------|------|----------|
| GET | `/api/category` | 公开 | 分页获取分类列表（`name`, `slug`, `description`, `current`, `size`） | 左侧分类目录、写文章分类选择 |
| GET | `/api/category/{id}` | 公开 | 获取指定分类详情 | 分类文章页 |
| POST | `/api/category` | 管理员 | 添加分类（`name`, `slug`, `description`, `sortOrder`） | 后台分类管理 |
| PUT | `/api/category/{id}` | 管理员 | 修改分类 | 后台分类管理 |
| PUT | `/api/category/{id}/status` | 管理员 | 切换分类状态（启用/禁用） | 后台分类管理 |
| DELETE | `/api/category/{id}` | 管理员 | 删除分类 | 后台分类管理 |

**分类数据结构**：`{ id, name, slug, description, sortOrder }`，`sortOrder` 越小优先级越高。

#### 8.3.3 文章接口（Article API）

| 方法 | 路径 | 权限 | 用途 | 对应页面 |
|------|------|------|------|----------|
| GET | `/api/article` | 公开 | 分页获取文章列表（`title`, `createBy`, `categoryId`, `status`, `startTime`, `endTime`, `current`, `size`） | 首页、分类/标签文章页、我的首页、用户首页 |
| GET | `/api/article/{id}` | 公开 | 获取文章详情（返回 `contentHtml` 用于渲染，`content` 用于编辑） | 文章详情页、关于页 |
| POST | `/api/article` | 管理员 | 保存/发布文章 | 写文章 |
| PUT | `/api/article/{id}` | 管理员 | 更新文章 | 编辑文章 |
| DELETE | `/api/article/{id}` | 管理员 | 删除文章 | 后台文章管理 |
| GET | `/api/article/{id}/like` | 需登录 | 查询当前用户是否点赞该文章 | 文章详情页 |
| PUT | `/api/article/{id}/like` | 需登录 | 点赞文章 | 文章详情页 |
| PUT | `/api/article/{id}/unlike` | 需登录 | 取消点赞 | 文章详情页 |

**文章列表查询参数说明**：
- `status`: `0`=审核中, `1`=已发布, `2`=草稿
- `createBy`: 用于"我的首页"和"用户首页"筛选特定作者文章
- `categoryId`: 用于"分类文章页"筛选

**文章数据结构（列表）**：`{ id, title, slug, summary, coverImage, viewCount, likeCount, commentCount, category, tags, updateTime, updater, createTime, creator }`

**文章数据结构（详情）**：列表字段 + `{ content, contentHtml }`

#### 8.3.4 评论接口（Comment API）

| 方法 | 路径 | 权限 | 用途 | 对应页面 |
|------|------|------|------|----------|
| GET | `/api/comment` | 公开 | 分页获取一级评论（`id`=文章ID, `current`, `size`） | 文章详情页 |
| GET | `/api/comment/child` | 公开 | 分页获取二级评论（`id`=根评论ID, `current`, `size`） | 文章详情页（展开回复） |
| POST | `/api/comment` | 需登录 | 发布评论（`articleId`, `content`, `parentId`, `rootId`） | 文章详情页 |
| DELETE | `/api/comment/{id}` | 需登录 | 删除评论及其子评论 | 后台评论管理、文章详情页（作者删除） |

**评论数据结构**：`{ id, content, likeCount, childCount, articleId, parentId, ipAddress, createTime, creator, level }`
- `level`: `0`=一级评论, `1`=二级评论
- `parentId`: 父评论 ID，一级评论为 `0`
- `rootId`: 根评论 ID，一级评论为空

#### 8.3.5 认证接口（Auth API）

| 方法 | 路径 | 权限 | 用途 | 对应页面 |
|------|------|------|------|----------|
| POST | `/auth/login/pwd` | 公开 | 用户名密码登录（`username`, `password`） | 登录页 |
| POST | `/auth/login/email` | 公开 | 邮箱验证码登录（`email`, `code`） | 登录页 |
| POST | `/auth/register` | 管理员 | 注册新用户（需管理员权限） | 注册页（后台） |
| POST | `/auth/refresh` | 公开 | 刷新 `accessToken`（自动携带 `refreshToken` Cookie） | 全局拦截器 |
| POST | `/auth/logout` | 需登录 | 登出（清除 `refreshToken`） | 全局导航 |

**登录响应**：`{ accessToken, expiresIn, userInfo: { id, username, nickname, avatar, role, status, lastLoginTime } }`
- `role`: `0`=管理员, `1`=普通用户
- `status`: `0`=禁用, `1`=启用

#### 8.3.6 用户接口（User API）

| 方法 | 路径 | 权限 | 用途 | 对应页面 |
|------|------|------|------|----------|
| GET | `/api/user/me` | 需登录 | 获取当前登录用户信息 | 全局（Header 头像/昵称）、我的首页、用户设置 |
| GET | `/api/user/{id}` | 公开 | 获取指定用户信息 | 用户首页、文章详情页左侧边栏 |
| PUT | `/api/user` | 需登录 | 更新用户信息/修改密码（`oldPassword`, `newPassword`, `confirmPassword`, `nickname`, `avatar`） | 用户设置 |

**用户信息数据结构**：`{ id, username, nickname, avatar, role, status, lastLoginTime }`

**头像更新流程**：先调用 `POST /file/upload?type=avatar` 上传图片获取 URL，再将 URL 传入 `PUT /api/user`。

#### 8.3.7 文件接口（File API）

| 方法 | 路径 | 权限 | 用途 | 对应页面 |
|------|------|------|------|----------|
| POST | `/file/upload?type={type}` | 需登录 | 上传文件（`type`: `cover`/`avatar`/`image`/`file`） | 写文章（封面图）、用户设置（头像）、Vditor（图片插入） |

### 8.4 接口调用注意事项

1. **关于页特殊处理**：`GET /api/article/1` 固定获取 ID 为 1 的文章作为关于页面内容，使用 `contentHtml` 渲染。
2. **标签文章页限制**：后端暂不支持按标签过滤文章，当前调用 `GET /api/article?status=1` 显示所有已发布文章，前端按标签名过滤展示。
3. **随机文章实现**：调用 `GET /api/article?size=5&status=1`，由后端随机排序返回 5 篇。
4. **我的文章状态筛选**：我的首页（`/user/me`）使用 `GET /api/article?createBy={currentUserId}&status={status}`，`status` 参数动态切换（全部时不传）。
5. **用户首页只展示已发布**：`GET /api/article?createBy={userId}&status=1`，无状态筛选 UI。
6. **评论嵌套加载**：文章详情页先加载一级评论（`GET /api/comment?id={articleId}`），点击"展开回复"再加载二级评论（`GET /api/comment/child?id={rootCommentId}`）。

### 10.1 首页（`/`）

- **背景图**：使用指定的静态资源图片作为背景，叠加暗色遮罩（`bg-black/40`）保证文字可读性。

- **中间主内容区**：文章列表分页展示。
  - API：`GET /api/article?status=1&current={page}&size=10`
  - 分页组件：方形按钮 + 硬边框。
- **右侧边栏**：
  - 随机文章：`GET /api/article?size=5&status=1`（后端随机排序）。
  - 标签云：`GET /api/tag?size=20`。

### 10.5 关于（`/about`）

- 路由路径：`/about`
- API：`GET /api/article/1`（固定获取 ID 为 1 的文章）
- 使用 `contentHtml` 渲染，布局同文章详情页（三栏）。
- 左侧边栏显示博主信息。

### 10.6 分类文章（`/category/:slug`）

- 展示指定分类的文章列表。
- 流程：
  1. `GET /api/category` 获取全部分类，建立 `slug` → `id` 映射。
  2. `GET /api/article?categoryId={id}&status=1&current={page}&size=10`
- 页面标题显示分类名称和描述。
- 分类数量 <= 8 时全部展示，> 8 时分页或滚动加载。

### 10.7 标签文章（`/tag/:slug`）

- 展示指定标签的文章列表。
- 流程：
  1. `GET /api/tag` 获取全部标签，建立 `slug` → `id` 映射。
  2. `GET /api/article?status=1&current={page}&size=10`（后端暂不支持按标签过滤）。
  3. 前端按标签名过滤展示（或显示全部文章并标注匹配标签）。
- 页面标题显示标签名称和颜色（使用标签的 `color` 字段）。

### 10.8 登录（`/login`）

**布局**：
- 不使用三栏布局。
- 居中卡片式登录框（`max-w-md`，`rounded-2xl`，`shadow-lg`）。
- 背景叠加噪点纹理（`noise-overlay`）。

**功能需求**：
- 用户名密码登录：`POST /auth/login/pwd`（`username`, `password`）
- 邮箱验证码登录：`POST /auth/login/email`（`email`, `code`）
- 登录成功后：
  - `accessToken` 存入 `localStorage`
  - `refreshToken` 自动在 `cookie` 中（http-only）
  - 调用 `GET /api/user/me` 获取用户信息存入 Pinia
  - 跳转首页或原目标页

### 10.9 后台管理（`/admin/*`）

**布局**：
- 不使用三栏布局。
- 左侧 Sidebar 导航（固定宽度，暗色背景）+ 右侧内容区（紧凑信息密度）。
- Sidebar 使用直角或微圆角（`rounded-sm`），暗色主题。

**管理页面清单与 API**：

| 页面 | 路由 | 主要 API |
|------|------|----------|
| 仪表盘 | `/admin` | 聚合 `GET /api/article`、`GET /api/category`、`GET /api/tag`、`GET /api/comment` 统计 |
| 文章管理 | `/admin/articles` | `GET /api/article`（分页 + 状态筛选）+ `DELETE /api/article/{id}` |
| 分类管理 | `/admin/categories` | `GET /api/category` + `POST /api/category` + `PUT /api/category/{id}` + `DELETE /api/category/{id}` + `PUT /api/category/{id}/status` |
| 标签管理 | `/admin/tags` | `GET /api/tag` + `POST /api/tag` + `PUT /api/tag/{id}` + `DELETE /api/tag/{id}` |
| 评论管理 | `/admin/comments` | `GET /api/comment`（按文章聚合）+ `DELETE /api/comment/{id}` |

### 10.10 写文章（`/write`）与编辑（`/write/:id`）

**布局**：
- 不使用三栏布局。
- 全宽编辑器，顶部固定工具栏。
- 左侧编辑区 + 右侧实时预览区（可选分栏）。

**功能需求与 API**：
- Markdown 编辑：Vditor 编辑器。
- 实时预览：Vditor 自带或自定义预览区。
- 封面图上传：`POST /file/upload?type=cover`，获取 URL 后填入表单。
- 分类选择下拉：`GET /api/category`，按 `sortOrder` 排序。
- 标签多选：`GET /api/tag`，胶囊形多选组件。
- 保存草稿：`POST /api/article`（`status=2`）
- 发布文章：`POST /api/article`（`status=1`，实际会被系统置为审核中 `0`）
- 编辑文章：`GET /api/article/{id}` 获取 `content`（Markdown 原文），`PUT /api/article/{id}` 保存。

## 14. 关键实现策略

1. **布局壳子（AppLayout）**：通过 Vue Router 的嵌套路由或条件渲染，让 `Login`、`/write`、`/admin/*` 不走三栏布局，其余页面自动套三栏 + 可选 Hero。
2. **Axios 拦截器**：
   - 请求拦截器：从 `localStorage` 读取 `accessToken`，附加 `Authorization: Bearer` 头。
   - 响应拦截器：捕获 401，调用 `POST /auth/refresh`，成功后重试原请求；刷新失败则跳转登录。
3. **主题切换**：Pinia 存储主题状态，`localStorage` 持久化，切换时给 `<html>` 加/减 `dark` class，过渡 `0ms` 硬切。
4. **噪点层**：全局 `fixed` 的 `div`，`pointer-events-none`，`z-index: 9999`，亮色/暗色均显示。
5. **Markdown 渲染**：`v-html` + `prose prose-base prose-slate dark:prose-invert max-w-none`，配合定制的代码块/引用块样式。
6. **Hero 区**：`GlitchText` 使用 CSS `text-shadow` 错位 + `clip-path` 切片动画；`TypewriterText` 用 JS 控制逐字显示 + 闪烁光标。
7. **我的文章状态筛选**：使用查询参数动态切换 `status`（全部时不传），切换时硬切无动画。
8. **评论嵌套加载**：文章详情页先加载一级评论，点击"展开回复"再按需加载二级评论，避免一次性加载过多数据。
9. **文件上传封装**：统一封装 `uploadFile(file, type)` 方法，处理 `cover`/`avatar`/`image`/`file` 四种类型，返回 URL 供表单使用。
10. **路由守卫**：
    - 全局前置守卫检查目标路由的 `meta.requiresAuth` 和 `meta.requiresAdmin`。
    - 需登录但未登录：跳转 `/login`，携带 `redirect` 参数。
    - 需管理员但非管理员：跳转 403 错误页。
